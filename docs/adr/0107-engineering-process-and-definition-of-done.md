# ADR-0107: Engineering process and Definition of Done

- **Status:** Accepted
- **Date:** 2026-11-01
- **Deciders:** Kamaal Khan (owner)
- **Plan refs:** plan.md §29, §27 (standing gates), principle 15–16 (§1.2)
- **Related:** ADR-0000, ADR-0020, ADR-0023, ADR-0046, ADR-0047, ADR-0049, ADR-0070, ADR-0106, ADR-0045

## Context

A multi-year, security-critical product with a broad surface (API, console, CLI, Terraform, SDKs, MCP) drifts unless "done" is defined and enforced the same way for every change. Parity across surfaces is a stated principle (one engine, many surfaces; everything is config-as-code).

## Decision

1. **Branching:**
   - Trunk-based on `main`, with short-lived branches (≤ 5 working days recommended) and a merge queue.
   - Squash merge with **Conventional Commits** titles. The changelog is generated by `git-cliff`.
   - Releases are cut from tags; release branches `release/x.y` are kept only for supported versions (ADR-0045).
2. **Reviews:**
   - 1 approving review by default.
   - **2** for PRs labelled `security` (auto-applied by path: `crates/auvora-{crypto,jose,oauth,saml,authz,authn,sessions,support,agents}`, `ee/`, auth middleware in SDKs, CI/release workflows).
   - CODEOWNERS enforce this. Authors can't approve their own PRs. Admin bypass is disabled.
3. **Spec-first:** OpenAPI (`api/openapi/*.yaml`) and the event catalog (`api/events/*.json`) change in the same PR **before or with** handlers. `oasdiff` blocks breaking changes on `/v1` (ADR-0020).
4. **Definition of Done.** A change is done only when all of these hold:
   - [ ] Unit + integration tests, **including negative/abuse tests** for security-relevant paths (ADR-0106).
   - [ ] A threat-model note (`docs/threat-models/<feature>.md` updated) for `security`-labelled changes (ADR-0049).
   - [ ] Audit events defined in the catalog and emitted; no secrets in events or logs.
   - [ ] Metrics/traces added (ADR-0040) for new endpoints and jobs.
   - [ ] **Surface parity:** Admin API + console + CLI + Terraform resource/attribute + config export/import (ADR-0070). Parity may lag by at most one minor release, and only when tracked as a `parity-debt` issue that blocks the next minor.
   - [ ] Migrations are expand/contract and N-1 compatible (ADR-0025); the upgrade test passes.
   - [ ] Docs page + example updated; doc snippets compile/run in CI.
   - [ ] i18n message IDs added (ADR-0104); accessibility checks pass for UI changes.
   - [ ] Feature flags for draft standards (plan §30) with a documented default.
   - [ ] Bench impact within the 5% budget (ADR-0105).
5. **Issue workflow:** GitHub Issues + Projects. Labels: `phase:Pn`, `area:*`, `security`, `parity-debt`, `good-first-issue`. Each phase has an epic linking its exit criteria.
6. **Signed commits** are required for maintainers. DCO isn't used because the CLA applies (ADR-0004); the CLA is checked by a bot.
7. **Dogfooding:**
   - The admin console and Auvora Cloud authenticate via Auvora.
   - `examples/b2b-demo` (Next.js + Go API) is built only on public SDKs and runs in the nightly E2E.
   - Internal tools never use private APIs.
8. **RFCs for large features:** features > 2 weeks of effort need a design doc in `docs/specs/` reviewed before implementation. If it changes an Accepted decision, it produces an ADR.

## Rationale

A strict, checklist-based DoD is cheaper than retrofitting parity, docs or security later. It operationalizes principles 12, 15 and 16.

## Alternatives considered

- **GitFlow:** long-lived branches conflict with a monthly release cadence.
- **Parity optional:** creates "console-only" features that break config-as-code.

## Consequences

- Positive: consistent quality; easier contributions.
- Negative: slower individual PRs. That's accepted, because there's no deadline pressure (ADR-0001).

## Fallback / revisit trigger

If the median PR lead time exceeds 7 days for 2 consecutive months, review the DoD for steps that can be automated. Security items are never dropped.

## Implementation notes

P0: PR template with the DoD checklist, CODEOWNERS, labels, merge queue, CLA bot, git-cliff, and doc-snippet test harness.

## Verification

- PR template checks (a bot verifies the checklist for `security` PRs).
- The CI parity check compares OpenAPI operations against Terraform schema and CLI commands, and reports gaps as `parity-debt`.
