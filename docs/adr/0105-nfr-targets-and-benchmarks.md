# ADR-0105: NFR targets and benchmarks

- **Status:** Accepted
- **Date:** 2026-11-01
- **Deciders:** Kamaal Khan (owner)
- **Plan refs:** plan.md §25, §23 of v0.2, §27 standing gates
- **Related:** ADR-0005, ADR-0006, ADR-0009, ADR-0033, ADR-0019, ADR-0045, ADR-0106, ADR-0107

## Context

v0.2 refused to state performance numbers until a benchmark suite existed. That's correct for marketing, but without targets the architecture can't be validated. v1.0 sets GA targets, and this ADR makes them binding together with how they are measured.

## Decision

1. **Reference hardware:**
   - 3 × `auvora` nodes, each 4 vCPU (x86-64, AVX2) / 8 GiB RAM.
   - PostgreSQL 16 primary with 8 vCPU / 32 GiB / NVMe, plus 1 sync replica.
   - 10 Gbit network, < 1 ms RTT. No Valkey unless a scenario says so.
   - It's defined as Terraform in `bench/infra/` (AWS c7i/r7i equivalents) and as a local Compose variant for smoke runs.
2. **GA targets** (binding; all p99 values measured server-side and at the load generator):

| Scenario | Target |
|---|---|
| `client_credentials` → JWT | ≥ 10,000 req/s cluster; p99 < 50 ms |
| Password login (Argon2id baseline; latency excluding hash time) | p99 < 150 ms; ≥ 1,000 logins/s with the hashing pool sized |
| Passkey assertion | p99 < 100 ms |
| Auth code + PKCE full flow (non-interactive harness) | p99 < 200 ms end to end |
| Refresh with rotation | ≥ 5,000 req/s; p99 < 60 ms |
| Introspection | p99 < 20 ms |
| JWKS / discovery | p99 < 5 ms; cache headers present |
| AuthZEN check (embedded ReBAC, warm, depth ≤ 5) | p99 < 5 ms; ≥ 50,000/s |
| Config propagation | ≤ 5 s p99 |
| Session/user revocation propagation | ≤ 5 s p99 in-region |
| Idle RSS per node | < 100 MB; cold start < 2 s |
| Scale | 10 M users/project tested (100 M design); 100,000 projects/cell |
| Degraded: Valkey down (Scale profile) | No errors; p99 ≤ 2× baseline |
| Degraded: Postgres failover | Writes unavailable ≤ 30 s; token issuance for valid sessions continues from caches where safe |

3. **Bench suite** `bench/`:
   - k6 scenarios; a Rust micro-bench (criterion) for JOSE, Argon2, Cedar, ReBAC and CEL hot paths.
   - Seeded datasets (1 M / 10 M users, 10k / 100k projects).
   - Fault injection via toxiproxy.
4. **Gates:**
   - Every PR runs criterion micro-benches. A > 5% regression on a tracked bench fails CI unless labelled `perf-accepted` with justification.
   - A nightly run on the small reference cluster.
   - The full suite on reference hardware before each minor release. Results are published in `docs/benchmarks/<version>.md` with raw data.
5. **Claims policy:** no performance claim is published unless it comes from a published bench run with a reproducible config.
6. **Pre-GA milestones:**
   - P1 exit: ≥ 2,000 token/s on one node.
   - P3: ≥ 5,000 token/s cluster.
   - P5: all targets.

## Rationale

Explicit, reproducible numbers make the architecture testable (Postgres-only, stateless data plane) and keep regressions visible. Published raw data supports the "provable" USP pillar.

## Alternatives considered

- **No targets until after the build:** design flaws would surface too late.
- **Vendor-style marketing numbers:** not reproducible, and against principle 12 of v0.2.

## Consequences

- Positive: performance becomes a tracked product feature.
- Negative: reference infra costs money. Mitigations: full runs only per minor release; nightly runs on the small cluster.

## Fallback / revisit trigger

If a target is missed at P5 by > 20% after profiling, an ADR either changes the architecture (e.g. role split, ADR-0005 trigger) or revises the target with evidence. GA isn't declared with a silent miss.

## Implementation notes

P0: bench harness skeleton. Datasets are generated by `auvora dev seed --users N --projects M`.

## Verification

CI perf gate; published benchmark reports; the P5 exit checklist links the report.
